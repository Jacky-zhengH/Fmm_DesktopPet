# 0.1.4 素材制作与任务拆分

核对日期：2026-10-19。本文是执行方案，尚未安装生图环境、消费云额度、生成候选图或替换运行素材。当前运行版仍为 0.1.3；功能与截边诊断见 [0.1.4 工作方案](PLAN_0_1_4.md)。

推荐主线：**百炼图像编辑生成关键姿势 → Photoshop 2024 局部精修与分层 → 少量手工补帧 → 程序驱动摆动和位移 → 桌宠内验收**。ComfyUI 作为后续可复用的本地制作工作台，先跑通小工作流，不让环境配置挡住第一张修复图。

## 1. 本机条件与工作环境选择

本次只读检查得到：

| 项目 | 实际结果 | 对本项目的影响 |
|---|---|---|
| CPU / 内存 | i7-14650HX；约 31.7GiB 可识别物理内存 | 足够做 Photoshop 分层、预览及轻量本地推理实验 |
| 显卡 | RTX 4060 Laptop；nvidia-smi 报告总显存 8188MiB | 8GB 档；不要把桌面 4060 Ti 16GB 的教程直接套过来 |
| 显存快照 | 检查时空闲约 6148MiB | 桌面软件也会占显存；剩余量随运行程序变化 |
| 磁盘快照 | C 余 30.4GiB；D 余 50.6GiB；E 余 63.9GiB；F 余 163.3GiB | 模型库建议放 F，先预留约 40～60GB；这是本项目容量预算，不是官方最低配置 |
| 已识别软件 | Photoshop 2024（25.0）、Blender 4.3.2、ImageMagick、FFmpeg | 精修和预览可以直接开始；本轮没有启动它们验证具体界面 |
| 未识别软件 | 已查的安装登记与常见目录中没有发现 ComfyUI、Aseprite、Krita | 不排除其他位置有便携版；当前不依赖它们 |

WMI 的 AdapterRAM 字段只报出约 4GB，不能据此判定这张卡只有 4GB；这里采用 NVIDIA 驱动工具的显存数据。

### 推荐环境

- **立即使用**：现有 Photoshop 2024 + 百炼控制台的图像编辑体验入口。图像编辑入口是否支持上传多参考图、区域编辑，按所选模型界面确认。
- **长期增加**：官方 Comfy Desktop 的一个独立本地实例，模型和输出放 F 盘。建议工作位置 `F:\AI\ComfyUI`；本轮只是建议，没有创建或安装。
- **后续可选**：需要大量逐帧工作时再考虑 Aseprite；不必为了修几个像素先购买新软件。Blender 暂不作为本轮必修工具，当前没有可直接复用的角色骨骼或分层模型。

ComfyUI 和桌宠的 Python 环境分开。不要往桌宠 `.venv` 安装 torch、CUDA 或大量扩展；生成工具、模型权重和云端 SDK 不进入桌宠 EXE。它们负责制作 PNG，玩家只下载成品程序。

## 2. 哪些交给 AI，哪些本地完成

| 任务 | 主要方式 | AI 的角色 | 验收物 |
|---|---|---|---|
| 呆毛封闭空隙白底 | Photoshop 局部选区和蒙版 | 无需生成 | 同位置原图 / 修复图，发丝与头饰未损伤 |
| 浅色外圈、零散杂点 | Photoshop 逐段检查与铅笔修边 | 只有难判断的形状可做参考 | 深浅背景都自然，保留原有有效浅色描边 |
| 走路发梢截断 | 先扩大画布，手绘补轮廓；困难段用局部 AI 候选 | 提供缺失头发的合理形状，不能宣称恢复原始笔画 | 两帧轮廓连贯，头脸和衣服不被重画 |
| 拎起姿势 | 参考图 + 姿势草图生成关键姿势，再手修 | 改变手脚和身体姿态 | 第一张认可后再做 2～3 帧 |
| 鼓脸 / 生气 | 优先只改眼眉和嘴；画不好时局部生成 | 提供表情参考，不重画全身 | 2～3 帧，角色辨识特征稳定 |
| 左右探头 | 草图规定边缘和手的位置，再生成 / 手修 | 提供探头姿势 | 左右各 2 个关键姿势；不把整张脸直接镜像交差 |
| 行走补帧 | 修好现有两帧后画接触 / 经过姿势；AI 辅助困难姿态 | 生成少量关键姿势草案 | 每朝向先做 4 帧循环，步态连续 |
| 摆动、回弹、探出缩回 | Qt 绘制与位置动画 | 无需生成 | 时间和幅度可控，命中区与画面一致 |
| 呼吸、Zz、怒气符号、气泡 | 优先程序或少量独立特效图层 | 复杂装饰才考虑生成 | 不把特效计入身体尺寸基准 |
| 锚点、状态冲突、定时返回 | 程序修改与测试 | 无需生成图片 | 提醒不丢、不重播、不抢走拖动后的新位置 |

不要把每帧都独立生成当成默认流程：相同 seed 也不能保证五官、衣服和头发完全一致。应从已认可的关键姿势派生后续帧，并尽量只改运动部位。

## 3. ComfyUI 到底是什么

ComfyUI 是把图像处理步骤连接成节点工作流的工具。模型才负责生成；ComfyUI 负责装载模型、传入参考图和遮罩、采样、保存结果。节点连接和参数可以保存为 JSON，下次换参考图和提示词即可复用。参见 [官方工作流说明](https://docs.comfy.org/basic-concepts/workflow)。

本地运行使用本机显卡；连接外部模型节点则是云端调用。Comfy Cloud、Partner Nodes 的计费账户也不等于阿里云账户，**在 ComfyUI 里点到千问相关节点，不代表它就能抵扣你的学生券**。百炼直连需要支持其端点、认证与图片输入的相应工具，先通过百炼官方控制台完成验证。

本项目分三套工作流，逐套增加复杂度：

| 工作流 | 节点概念 | 先验证什么 |
|---|---|---|
| W1 基础图生图 | Load Image → VAE Encode → KSampler → VAE Decode → Save Image，另接模型与正负提示词编码 | 输入输出是否正确、风格变化与显存情况 |
| W2 局部修复 | 图像 + 手绘 mask → 对应模型的 inpaint 工作流 → 解码 → 与原图按 mask 合成 | 只有指定区域改变；先看 mask 预览，不猜透明通道方向 |
| W3 姿势与身份控制 | 角色参考 + 姿势线稿 → 匹配模型家族的参考 / ControlNet 条件 → 采样 | 轮廓跟草图，脸和配饰像同一角色 |

这只是节点配方，尚不是已运行验证的工作流 JSON。模型家族不同，装载器、参考图节点和采样参数不同，不能把 SDXL 的 ControlNet 或 LoRA 随意接到 Qwen / FLUX。

### 本机的安装与首轮验证步骤

1. 从 [官方 Windows 安装页](https://docs.comfy.org/installation/desktop/windows) 获取 Comfy Desktop，创建独立本地实例，选择 NVIDIA 路线；模型和输出目录选 F 盘。官方桌面版的安装空间不包括之后下载的大模型。
2. 第一套只装一个 SDXL Base 模型，使用官方 / 模型作者提供的基础配方；参考 [SDXL 官方模型卡](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0)。下载前记录模型名、来源、文件校验值与使用许可。
3. batch=1，先用 512 或 768 方图检查显存与耗时；这只是环境烟雾测试，SDXL 的最终画质再用其适合的 1024 档验证。暂不同时加 Refiner、多个 ControlNet、超分辨率和视频节点。
4. W1 的试验起点可设 20～30 steps、CFG 5～7、denoise 0.2～0.4，固定 seed 比较单个参数；这些仅是 SDXL 图生图试验范围，不适用于所有模型。大幅改变姿态时低 denoise 通常不够，改用草图条件或编辑模型。
5. 如果显存不足，先降低测试分辨率、关闭其他占用显存的任务，再试环境自带的内存卸载选项；没有实测前不承诺秒级出图。记录单张时间、峰值显存和角色一致性。
6. W1 稳定后才加 W2，再按需要加 W3。每次增加一类组件后保存能运行的版本；不一次导入几十个来源不明的自定义节点。
7. 保存工作流 JSON、节点版本、模型校验值、输入图、提示词、seed 和输出编号。版本升级在另一个实例验证，保留可用实例。

SDXL 是本机学习与控制流程的保守起点，不代表它在本项目上的出图质量已经胜过云端编辑模型。参考控制可后续研究 [IP-Adapter 原作者项目](https://github.com/tencent-ailab/IP-Adapter)；大头小身体角色的 OpenPose 自动识别可能不可靠，先用手画轮廓 / 线稿比直接套真人骨架更容易排查。

## 4. 当前模型怎么选

下面是结合本项目约束的试用顺序，不是已完成的模型画质排行榜。每个候选都必须用相同任务实测。

| 候选 | 适合试的工作 | 本项目建议 |
|---|---|---|
| Qwen-Image 3.0 / 3.0 Pro 云端编辑 | 多参考约束、局部修改、关键姿势 | 首选试验对象；兼顾已有阿里云额度。控制台是否可用及学生券覆盖另核对 |
| Qwen-Image-Edit Max / Plus | 原图编辑与局部修复候选 | 券专区没有新模型时的备选；固定具体 model ID，别把不同版本混成同一组实验 |
| Wan 2.7 Image / Pro | 连续图像与多个姿势探索 | 备选；官方支持连续图像能力，但不能据此认定能直接产出合格游戏序列帧 |
| SDXL Base 1.0 本地 | 学习可复现的图生图、遮罩和结构控制 | 8GB 机器先从这一档实验；逐步增加控制条件 |
| FLUX.2 Klein 4B 本地 | 生成与多参考编辑 | 进阶试验项；官方页面列约 8.4GB，而另一官方模型卡列约 13GB，口径 / 配置不同。8GB 不能保证直接舒适运行，量化或 CPU 卸载需要实测 |

模型能力依据：[阿里云图像模型目录](https://www.alibabacloud.com/help/en/model-studio/image-model/)、[BFL Klein 官方介绍](https://bfl.ai/models/flux-2-klein)、[BFL 官方 FP8 模型卡](https://huggingface.co/black-forest-labs/FLUX.2-klein-4b-fp8)、[ComfyUI Klein 配方](https://docs.comfy.org/tutorials/flux/flux-2-klein)、[Google 发布记录](https://ai.google.dev/gemini-api/docs/changelog)。云端商用型号不等于有同名权重可直接下载到本机。

本对话已有的生图工具也能用于关键姿势试样。真正生成时单独记录使用渠道，不把它与百炼抵扣额度混算。

暂不把整段 AI 视频、自动光流补帧或 LoRA 训练列为必经步骤。视频可先用于观察动作节奏；光流会在头发、手脚交叠时产生混影，抽帧不能自动解决角色漂移。现在只有少量且部分重复的素材，先做稳定关键姿势，比用这些图立即训练角色 LoRA 更容易验收。后续若积累了足量经审定、视角和姿势多样的样本，再独立评估训练。

## 5. 300 元学生券怎么用

用户确认券可以用于千问 AI 平台等阿里产品。官方高校计划说明支持百炼费用，券自领取起一年有效；活动页同时规定，具体商品范围与抵扣结果按用券专区及订单为准。参见 [百炼高校计划](https://help.aliyun.com/zh/model-studio/introduction-to-yungongkaiwu)、[官方活动详细规则](https://university.aliyun.com/action/cncc2025)。因此可将百炼作为主试验渠道，但还不能认定账号里的每一种图像模型、GPU 实例或套餐都受此券覆盖。

操作顺序：

1. 进入阿里云费用与成本 / 卡券管理，查看这张券的到期日、剩余额度、适用产品、地域及消费类型。
2. 从高校活动的用券入口查看大模型商品；先找能上传参考图的图像编辑型号。只支持文字模型的额度不能代替图片编辑额度。学生券也不能直接当作千问网页会员或其他平台余额。
3. 核对所选模型的实际 ID、地域，以及是否需要购买指定资源包；在订单预览中确认抵扣。若是按量抵扣，先用最小调用量核对账单明细。确认前不批量提交。
4. 第一轮限制为 10～20 元或等值券额，选出一个能保留形象的模型再继续。余额提醒不等于强制停用，批处理本身也要限制张数和并发；达到本轮上限就停。
5. 记录真实的抵扣明细、消耗张数和留用张数。有效成本按“每张认可素材”计算，不按模型宣传的最低单张价格比较。

官方 [百炼价格页](https://help.aliyun.com/zh/model-studio/model-pricing) 在核对时列出北京地域 Qwen-Image 3.0 Pro：1K 输出 0.25 元/张、输入 0.02 元/张。仅用于预算举例：每次两张输入、一张输出约为 `0.25 + 2 × 0.02 = 0.29 元`；24 次约 6.96 元，100 次约 29 元。实际按所选模型、地域、输出数量、免费额度与订单计费，**不是承诺这些调用均能抵券，也不是成品数量保证**。

建议先给本轮制作设 100 元上限：20 元模型对照、40 元动作候选、20 元定向返修、20 元余量。剩余 200 元保留给后续阶段。它是支出分配建议，没有实际下单。不要为这批小素材先购买长期 GPU 云主机；只有本地与云端编辑均达不到目标、且确需运行特定模型时，再比较租 GPU 的时长、存储与下载成本。

## 6. 第一轮模型对照：用小样选工具

选两个账户实际可用的编辑模型，例如 Qwen 3.0 Pro 与 Edit Max；若券只覆盖其一，就先测一个，另一家仅在已有额度时对照。

| 试题 | 输入 | 每个模型输出 | 判定重点 |
|---|---|---:|---|
| 走路右下发梢补全 | 原帧 + 扩展画布 / 遮罩 + 母图 | 3 张候选 | 局部修复，脸和服装是否被改动 |
| 拎起中立姿势 | 母图 + 干净运行图 + 简单姿势草图 | 3 张候选 | 头身、垂落手脚、发饰和异色瞳 |
| 轻微鼓脸 | 干净正面图 + 仅脸部编辑范围 | 3 张候选 | 是否只改变表情，发丝是否漂移 |
| 边缘探头 | 母图 + 方向草图 | 3 张候选 | 方向、扶边手势、可见区域 |

两个模型最多先做 24 张候选，可分多次返回单图；不是要求每张图里同时塞入多个动作。无 seed 控制的服务记录请求编号；有 seed 时一并记录，但不把它当身份锁定工具。

评分建议：角色一致性 40%、动作可读性 20%、轮廓 / 透明边缘 20%、精修工作量 20%。异色瞳、爱心发饰、手脚数量或关键服饰错了直接退回，不用“总分高”掩盖。每项记下还需要哪些修改；同一任务连续两轮仍大幅改脸时，调整草图 / 编辑范围或换模型，不继续盲抽。

## 7. 一张素材的完整制作流程

1. **建立角色基准**：母图负责形象，认可的运行图负责像素颗粒与颜色；标明两者用途，不能让模型把 JPG 粉色背景学成角色的一部分。
2. **画姿势草图**：PS 用几条线标出头、身体、手脚和支点。拎起、探头的要求先画清楚，不用长提示词弥补模糊姿势。
3. **生成一个关键姿势**：一次只改一项；脸、头饰、衣服和比例列为固定条件。提示词见 [模板](art/PROMPTS_0_1_4.md)。
4. **先审形象，再修边**：姿势和角色不像就退回；不要花半小时修一张最终不能用的图。
5. **PS 分层精修**：脸、前发、后发、身体、衣裙和特效按需要拆层；分层之后要补被遮住的部位，现有整图不能自动成为完整可动模型。
6. **从认可帧派生后续帧**：鼓脸可以只改脸，拎起可以只改手脚和发梢；大姿势变化再调用生成。每帧共享身体基准和画布位置。
7. **检查透明与像素规则**：输出 PNG RGBA；确认实际 alpha，而不是画出来的棋盘格。模型不支持真透明时，先取得便于处理的纯色背景再局部抠图；不能把所有白色一起删除。
8. **检查颗粒一致性**：512×512 是文件分辨率，不等于 512 格真实像素画。保留现有画面作比对，先确定基准网格，再决定是否做全套像素重整；简单“马赛克 + 最近邻”不能自动变成优秀像素动画。
9. **生成对照预览**：原图 / 候选图，白底 / 深灰 / 棋盘，静帧 / 循环，桌宠 160 / 200 / 300 / 400 显示尺寸。预览可以用已有工具合成，不改变原文件。
10. **用户审图后接入**：仅通过的 PNG 进入 `app/assets/sprites/`；同步元数据和回归。单纯放进 `image/` 不会自动加载，EXE 也需要重新打包才含新图。

## 8. Photoshop 2024 可以马上照做的修图

以下在候选副本上操作，PSD 保留图层；不要直接覆盖运行 PNG。具体工具栏位置可能随工作区不同，但核心工具在本机版本已有。

### A. 呆毛封闭白底

1. 打开 `app/assets/sprites/idle.png`，另存工作 PSD；保留一层锁定原图，复制一层作为修复层。
2. 底部放深灰、白色两层测试底，轮流显示。放大到 800% 左右，先看发丝和头饰的边界。
3. 魔棒启用“连续”，容差从约 5～10 小范围开始；局部像素修边时取消抗锯齿、羽化为 0。只点呆毛内部白底，确认选区没进入头饰和高光；复杂区域分小块选择。
4. 给修复层添加白色蒙版，选中蒙版缩略图，在当前选区内填黑隐藏白底，再取消选择。不要在角色图层全局删除白色。
5. 在蒙版上用小铅笔补齐残余；误伤的发丝用白色恢复。空隙应该透出测试底色，白头饰仍保持白色。
6. 关掉测试底，导出透明 PNG 到候选目录。其他正面状态可复用经过检查的局部蒙版；每张仍要单独核对边界，不能盲贴同一坐标。

魔棒的连续与容差设置依据 [Adobe 官方说明](https://helpx.adobe.com/photoshop/using/tool-techniques/magic-wand-tool.html)。

### B. 走路截边

1. 打开 `walk_0.png`，另存 PSD。使用“图像 → 画布大小”，不是“图像大小”。例如把 284×512 改成 512×512、居中，左右各增加 114 像素透明空间，人物不缩放。
2. 保留原图层；在新图层用铅笔延续右下长发轮廓和发丝。先从附近取样描边与填色，不先用柔边画笔、模糊或任意大范围涂抹。
3. 左侧与右侧上方发梢同样检查；新画线条要闭合到原有轮廓，避免只把截口拉长。
4. 画不出自然发梢时，把扩展后的画布与编辑区域交给图像模型，采用模板中的局部补全要求；拿回候选后只合成需要的补画区域，原头脸和衣服使用原图保留。
5. 认可一帧后，将新的静态轮廓规则用于 `walk_1`，保留两帧原来的手脚动作差异；不能用一帧覆盖两帧。
6. 按实际补画偏移更新锚点。补发梢改变了非透明外框，程序不能继续把外框简单拉齐当作身体尺度，否则可能再次出现走路变小。

画布扩展的原理与入口见 [Adobe 官方说明](https://helpx.adobe.com/ca/photoshop/using/adjusting-crop-rotation-canvas.html)。仅扩画布不代表补画已经完成。

### C. 生气与少量补帧

先把认可的表情放到独立脸部层，其余身体保持原图。窗口 → 时间轴 → 创建帧动画，通过复制帧和切换表情层建立 2～3 帧预览。PS 的 Tween 主要插补位置、透明度与效果，**不会自动发明一张正确的新手脚姿势**。参见 [帧动画](https://helpx.adobe.com/photoshop/desktop/add-video-and-animation/create-animation-frames/create-frame-based-animations.html)、[Tween 的范围](https://helpx.adobe.com/photoshop/desktop/add-video-and-animation/create-animation-frames/create-frames-using-tweening.html)。

时间轴用于预览；游戏用素材仍分别导出 PNG。最近邻缩放适合保留已有硬像素，但反复缩放或任意角旋转再回写会破坏网格；程序实时旋转与原始像素稿分开处理。


候选名示例：`fmm_drag_front_key01_r01.png`、`fmm_walk_left_key02_r02.png`。`left/right` 指角色面向屏幕方向，角色自身左右特征另外在基准中定义。小写英文和两位编号便于脚本处理；旧运行文件名保留兼容，接入时由清单映射。

PS 工作稿不放在可清理的 build。模型权重放项目外，不提交 Git；工作流不得包含 API Key。参考图、选中的候选 PNG、提示词和诊断可版本化，记录候选状态 `draft / review / accepted / rejected`。只有明确认可才能标 accepted；大体积 PSD 如需团队备份另定方案，不偷偷把整个模型库推到 GitHub。

每组序列使用统一画布和锚点；明确身体基准框、脚底、拎起支点和边缘支点。朝向改变时按人物自身左右关系与透视检查异色瞳和发饰，不能只要求所有角度“画面左眼永远绿色”。
