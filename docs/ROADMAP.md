# 开发计划

| 阶段 | 目标 | 状态 |
|---|---|---|
| 原版留档 | 保存原作者源码和六张图片 | 已完成，Git 标签 `v0.0.0-original` |
| 0.1.x | 基础交互、缩放、吸附、UI，再补素材与动作 | 已发布 0.1.3；正在制作 0.1.4 |
| 0.2.x | 下一阶段的系统功能 | 第一阶段结束后再定 |

0.1.4 的六张旧素材修复图已接入标准版源码。接下来做动作与定时提醒之间的协调，再做拎起轻晃、连续点击生气、边缘探头和行走补帧。新动作与调度尚未实现；源码界面版本号和已发布 EXE 仍为 0.1.3，EXE 尚未重新打包。[具体方案与验收](plans/0.1.4.md) · [修复对照](../image/review/0.1.4/comparison.png)

普通版功能开发分三批，每批完成后集中检验，交用户验收。

1. **软件查更。** 已实现读取公开 GitHub 正式发布、在设置中手动或自动检查以及打开发布页，待验收。
2. **本地日历事件。** 计划先做本地存档和单次、每年提醒规则，再做添加表单、日期标记和打开日历时的气泡提醒。
3. **气泡菜单动效。** 计划先做三颗气泡依次展开和收起，再做点击反馈、面板过渡和减少动画设置。

之后建议按下面顺序推进：

1. **互动动画与动作管理。** 沿用 Python / PySide6，先统一画布、比例、脚底和动作退出规则；建立动作协调器，使拖动可以打断演出、提醒结束能恢复原状态。逐步拆分 `BubbleUI` 的界面、对话和计时职责。
2. **小规模养成与报时。** 从心情、饱食、投喂间隔、存档与少量台词开始；报时作为可关闭的独立服务，与定时提醒共用动作管理。
3. **音乐与直播连接。** 先验证系统媒体会话能否读取当前曲目和暂停/继续，QQ 音乐、网易云的具体版本需实机确认。直播先提供房间链接，再验证开播状态、网络失败和通知频率；请求不能阻塞界面。

后续统一按标准用户版开发，较大改动分段提交、测试并推送，验收后通过 PR 合并。现有喂食只有概念演示，没有养成存档。音乐、直播与报时都还不是当前功能。已有功能查 [简易指引](QUICK_GUIDE.md)，版本变化查 [更新记录](../CHANGELOG.md)。
