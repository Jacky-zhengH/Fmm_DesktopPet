# 0.1.4 · 互动动画与素材修复

这是下一版的工作方案。修复前检查基线为 `343f29e`；六张旧素材的修复图现已接入标准版源码。以下新动作和调度仍待实现，继续作为 0.1.4 的工作内容。源码界面版本号和已发布 EXE 仍为 0.1.3，本轮尚未重新打包 EXE。

目标：拖起来像被拎起，连续戳会有一点小脾气，靠近屏幕两侧会藏起来探头；同时整理动作调度，让这些互动与睡眠、菜单、定时提醒相处正常。继续使用 Python / PySide6 和透明 PNG，不需要先换引擎。

素材分工、本机环境、ComfyUI 配方、模型试样、学生券使用和任务拆分见 [素材制作执行方案](../art/WORKFLOW_0_1_4.md)，可复制的提示词另见 [模板](../art/PROMPTS_0_1_4.md)。

## 当前实际能力

| 项目 | 当前实现 | 对新动作的影响 |
|---|---|---|
| 刷新 | `character.py` 的 Qt 定时器间隔为 16ms；实际刷新受系统调度影响 | 这是画面更新频率，不代表有约 60 张不同姿势 |
| 行走 | 两张 PNG，以 8fps 交替；位置按时间移动 | 只提高 fps 会更快重复两张图，应补关键姿势与过渡 |
| 待机 / 睡眠 | 单张图加程序缩放；眨眼替换整张图，睡眠另画 Zz | 目前不是骨骼动画，也不是每个部件都已独立分层 |
| 拖动 | 鼠标跟随，进入 drag 状态，但没有 drag 素材，实际回退到 idle | 必须增加拎起姿势，不能只在配置里提高帧率 |
| 新状态 | Character 只加载五种固定状态；非循环序列停在最后一帧 | angry、peek 需要注册、触发、完成通知和恢复规则 |
| 位置与大小 | 按动作的透明内容范围统一高度、脚底对齐 | 此前的走路缩小已修复；新姿势需明确锚点，不能再按每个姿势的外框盲目拉齐 |
| 提醒 | BubbleUI 负责走到中央、说话、返回，也直接切换角色状态 | 与窗口和 Character 分散的状态切换需要统一管理 |

| 动作细节少 | 两帧行走之外缺少拎起、生气、探头姿势 | 先审关键姿势，再补少量中间帧；不以大量重复图或整体摇摆代替所有身体动作 |

母图是有背景的 JPG，适合锁定形象，不是可以直接替换的透明像素素材。512 的图片边长也不等于有效像素绘制网格；先核对现有线条颗粒和色板，再确定补帧规格。

素材修复必须给出原图 / 候选图在深色、浅色、棋盘背景上的对照，并经用户看过再替换。保留原图和修改记录；修复与新动作分别提交，便于独立回退。

### 两张走路图的截边专项检查

用户指出的截边确实存在于修复前源图中，[边界数据](../../image/review/0.1.4/audit/walk_edge_audit.json) 记录了接触原画布左右边缘的像素。两帧右下长发都有平直截断，左侧发梢也贴到边界。本轮接入的修复图已补右侧发梢；左侧细小接触点尚未重画。左右移动时程序还会镜像，因此同一个缺口在屏幕上可能换到另一侧。旧诊断图可从 Git 历史恢复。

| 源文件 | 左边界 x=0 非透明像素数 | 右边界 x=283 非透明像素数 | 右下连续接触边界的 y 区间 |
|---|---:|---:|---|
| walk_0.png | 31 | 98 | 353～417，共 65 行 |
| walk_1.png | 31 | 101 | 350～417，共 68 行 |

坐标为原图像素，区间包含两端，阈值为 alpha > 0。更高透明度阈值下仍有大片边缘接触，并非只有几个几乎看不见的散点。顶部和底部画布边界均没有非透明像素；这次最明显的问题在横向裁边。完整数据见 [边界检查记录](../../image/review/0.1.4/audit/walk_edge_audit.json)，可用 `tools/diagnostics/audit_walk_edges.py` 复查。

仅凭“碰到画布边界”不能判断任何图片都被裁过；这里还结合了发丝填色和轮廓被直线截开的可见证据。现有文件不足以追溯当初在哪一步裁切，也无法精确恢复被截掉的原始笔画。修复时需要参考角色形象补画、审图，而不是宣称能无损还原。

另检查了当前程序的绘制范围：在 160 / 200 / 300 / 400 大小、两帧、两个朝向的 16 组计算中，非透明内容范围都在窗口画布内，见 [几何检查记录](../../image/review/0.1.4/audit/walk_geometry_check.json)。这支持“素材已有截边”的判断；该检查只验证 offscreen 绘制计算，不代替 Windows 原生 mask、缩放和屏幕边缘的实机验证。

两张走路图的主要修复和本轮接入已完成。后续新增动作继续预留摆动范围，保留角色比例与脚底基准，按批审图后接入。

## 三个互动的具体行为

以下数值用于第一轮试手感，不是已生效的设置。

### 拎起与轻晃

继续用当前超过 6 个 Qt 逻辑像素的移动阈值区分点击和拖动。进入拖动后换成拎起姿势，脸部略惊讶、手脚自然下垂；慢拖轻晃，快拖倾斜稍大，停止后逐渐回正。

先做 2～3 张关键姿势，用经过平滑的鼠标速度驱动小角度旋转，建议上限 ±8°；松手后约 200～350ms 收回摆动。人物跟随点保持连续，不要突然从鼠标下跳到另一位置。绘制旋转可以围绕头部支点，但需补偿按下位置；不加入甩飞、重力坠落等额外行为。

旋转后的范围、窗口留白和原生 mask 要同步计算，否则容易裁掉呆毛或出现“看得见、点不到”。现有 mask 是矩形范围，并不是精确的逐像素鼠标穿透。Qt 的 setMask 还会影响可见区域，不能只把它当作鼠标热区。[QWidget 文档](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QWidget.html#setMask)

睡眠时明确拖动视为叫醒；松开回待机。只是打开菜单、预览喂食或设定定时器，仍保留原有睡眠语境。

### 连续点击后小小生气

建议 1.2 秒内有效点击 4 次触发，持续约 1.5～2 秒，触发后冷却约 6 秒。使用 2～3 张表情关键帧配合轻微鼓脸、扭头或小幅抖动，气泡例如“唔……不许一直戳啦！(｀へ´)”。结束回到正常待机。

只统计在主体上完成的点击释放。拖动、Ctrl+滚轮、菜单按钮和打开二级面板不计数；睡着时第一次点击只叫醒，不纳入连击。避免单击开心台词在连击中反复闪烁，可让新表情接管同一气泡。

生气不锁住鼠标，也不影响右键退出、睡眠或拖走。它只是一段互动，不扣数值，不提前绑定尚未落地的养成系统。

### 左右边缘隐藏探头

仅在桌面左右外缘实现，先保留顶部和任务栏原有吸附方式。用户把芙芙放在侧边后，待机约 2～3 秒才缓缓侧藏，露出脸和足够的可拖区域；建议保留约 40%～50% 身宽，不能只剩一条难点中的缝。

首次进入要停留且处于空闲状态，冷却约 20 秒，避免松手就消失。鼠标靠近时探出，点击完整出来，拖动立即退出探头；露出时悬停可照常打开菜单，菜单展开期间不再次藏起。睡眠、提醒演出、打开面板期间不主动触发。

现在 constrain 会把主体完整限制在屏内，探头需要局部例外，不能删除全局边界保护。保存最后一个完整可见的位置，隐藏坐标不直接写入存档；重新启动或屏幕断开后回到可见位置。定时提醒开始前先退出隐藏姿态，提醒结束返回可见位置，不把返回路径指向屏外。

多显示器相接处不是可藏身的外缘：只有侧边对应的高度区间没有相邻屏幕才可隐藏。第一轮实机需要检查负坐标、不同缩放比例、侧置任务栏和屏幕热插拔；侧置任务栏区域不作为隐藏点。

## 动作管理怎么拆

建议增加轻量 `ActionDirector`，统一处理动作请求、是否允许打断、完成或取消、需要恢复的上下文。先整理当前调用，不为这几个动作引入完整游戏引擎。

- 输入层只报告点击、开始拖动、速度和边缘停留，不各自修改提醒标志。
- Director 决定当前行为；Character 负责播放姿势和提供完成信号；窗口负责位置、变换和命中范围；BubbleUI 显示菜单与话语。
- 将定时到期、去中央、提醒、返回逐步从 BubbleUI 抽到独立控制器，统一向 Director 请求动作。沿用已有 Qt 属性动画移动位置。[QPropertyAnimation 文档](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QPropertyAnimation.html)
- 区分基础模式（醒着 / 睡眠）与短暂动作，记录原位、吸附、显示器和是否已提醒；被打断时不要仅靠“回到 idle”清理一切。

规则按具体场景确定，不能只排一张优先级列表：

| 场景 | 预期规则 |
|---|---|
| 用户拖动 / 手动睡眠 / 退出 | 立即响应，停止冲突演出；拖动后的新位置优先，不能被过期返回回调拉走 |
| 拖动时定时到期 | 暂存一次到期事件，松手且界面空闲后提醒；不能丢掉，也不能重复 |
| 生气 / 探头时定时到期 | 结束低优先级姿态、恢复安全坐标，再去中央提醒 |
| 提醒尚未送达就被打断 | 保留未送达事件，合适时重试 |
| 提醒已送达、返回途中被拖走 | 不再重复提醒，不强制返回旧位置 |
| 菜单显示 | 暂停自主走动和新互动；待机呼吸、睡眠呼吸与 Zz 继续，不停止整个刷新计时器 |
| 短动作结束 | 明确通知 Director，再恢复合适状态；非循环帧不能永远停在最后一张 |

取消动作需使旧回调失效，只有当前动作能提交结束状态。连击、拖动速度和隐藏姿态属于临时状态，不写进用户存档；旧设置文件继续兼容。

## 动作素材的规格与制作

先在配置里明确身体基准框、脚底锚点、拎起支点、边缘锚点、朝向、循环及结束行为。旧字段有默认值，已有素材继续可用。同一动作的序列帧共享基准，不跟着每帧透明外框改变大小；拎起、低头也不拉伸到站立身高。

爱心、怒气等特效可以逐步单独画，不计入身体缩放基准。当前 happy 的爱心已烘焙在整图中，要先标定身体范围，不能假定已能独立控制全部部件。新增待机序列也要处理眨眼：当前有序列帧就不再运行原有随机眨眼逻辑，不能补了呼吸反而丢掉眨眼。

行走还需核对位移与步频：当前自主走动是 90 逻辑像素/秒，而提醒移动按距离估算约 260 逻辑像素/秒，并受 700～3500ms 时长限制；它们使用同一组 8fps 行走帧。补帧后按角色显示大小和移动速度调整步频或位移，避免去中央时出现明显滑步，不能只统一写一个更高 fps。

第一轮素材量建议：行走每朝向 4 帧，拎起 2～3 个关键姿势，生气 2～3 帧，左右探头各 2 个关键姿势；先做单姿势小样审形象，再补齐。独立睡姿视余量安排。不是预先承诺生成几十张完整图片。

制作流程：母图锁定颜色与形象 → 单张关键姿势 → 检查头身比例、画面左绿眼右红眼及爱心发饰 → 局部修边 → 少量补帧 → 同尺寸循环预览 → 深浅背景对照 → 用户审图后接入。可以用生图模型辅助关键姿势；模型和费用另行选择。视频生成或自动插帧是否适合要先用短样片验证，不把抖动的五官、发饰或混色边缘直接作为成品。

## 开发与验收顺序

1. **素材基线与接入**：六张旧素材修复并接入源码已完成，保留前后对照和哈希。接下来补明确的身体框、脚底、拎起支点和朝向约定。
2. **动作调度**：迁移现有点击、拖动、睡眠、提醒路径。先用现有图验证完成 / 取消 / 排队 / 返回，避免一边换图一边猜状态问题。
3. **拎起与连击**：接入关键姿势、小角度摆动、连击窗口及冷却，验收操作手感和菜单兼容。
4. **边缘探头与补帧**：处理侧边约束、可拖区域、多屏边界和提醒返回，再完善行走循环。
5. **完整回归后发布**：更新实际功能指引和 0.1.4 版本说明，用户验收后才标记版本、打包与发布。

验收至少覆盖：80% / 100% / 150% / 200% 角色大小、像素与平滑模式、深浅桌面、动作切换不跳尺寸 / 脚底、拖动旋转不裁切、普通点击不误触生气、睡眠与菜单仍有呼吸、左右探头都能找回主体、任务栏点击不被透明窗口挡住。

提醒专项覆盖：待机 / 睡眠 / 拖动 / 生气 / 探头 / 面板打开时到期，中央演出被打断、返回途中拖动、过程中调整显示器；检查提醒次数、当前位置、吸附和睡眠恢复。自动测试用可控时间，不依赖真实等待；实际 Windows 窗口的 mask、跨屏及鼠标行为仍需实机验证，offscreen 测试不能替代。

运行回归命令为 `.venv/Scripts/python.exe -m unittest discover -s tests -v`，人工入口继续用根目录 `run.bat`。新增序列需检查编号连续、透明通道、关键特征和资源缺失回退。记录相同场景下的 EXE 大小、空闲 / 拖动时 CPU、工作集；没有测量前不承诺体积或性能数字，也不引入运行时视频解码和在线模型依赖。

这版完成三个互动、主要素材修复和调度即可；喂食存档、音乐电台、直播联动留给后续单独安排。后续统一维护标准用户版。开发关联 Issue / PR，在独立功能分支按可验证的小块提交、测试并推送，通过 CI 后合并 `main`；已发布标签保持不变。
